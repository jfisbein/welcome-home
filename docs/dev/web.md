# Web pages

Read when: adding or changing a page, a template, a script, a style, a message in the bundles, or how a lock's time zone is shown.

See also: [conventions](conventions.md) (texts only in the bundles), [testing](testing.md) (browser tests), [features](../features.md).

## Rules

- **Web**: Thymeleaf templates, Pico CSS classes; every page's `<html>` carries `th:lang="${#locale.language}"` and `th:attr="data-theme=${theme}"`; every signed-in page starts with `fragments/layout :: menu('<section>')` (home, locks, settings or admin), and configuration's pages add `settings('<section>')` (nuki, preferences, notifications, passkeys, activity or account); guests' attempts are drawn by `fragments/attempts :: table(attempts, withLock)`, on the home page and in the history alike; a lock's time zone is shown by its name, `${@timeZoneNames.of(zone, #locale)}` ("hora de Europa central"), never its id, except where the owner chooses one; a page that must start no session sets `sessionless`, so the layout leaves out the CSRF meta tags. Two Thymeleaf traps: a fragment selector also matches elements by name, so no fragment is named like an element (hence `menu`, not `nav`); and `th:replace` runs before `th:if` on the same element, so a conditional fragment goes inside `<th:block th:if>`. The CSP also forbids inline styles: scripts change styles only through the DOM (`element.style`), never `<style>` or `style=` in markup; CSRF on every form, HTML forms send PUT/PATCH/DELETE through `_method`. JS in `static/js/`, one small file per behavior, no inline scripts (CSP `script-src 'self'`); a script's texts come from its page, as hidden lists or `data-*` attributes. Routes taking an id must be covered by `OwnerIsolationTests` (a guard test lists them).

## Decisions

| Decision | Why |
|----------|-----|
| A lock's time zone shown by its name, never its id; Spain's zones named by the bundles; a new lock imported with the server's zone when Nuki's keeps the same time | An id such as `Europe/Berlin` is technical, and wrong for a lock in Madrid, which Nuki reports so as it has one zone per region. Java names Madrid "hora de Europa central", so the bundles name Spain's two zones ("hora de España peninsular", "hora de Canarias"), where the owners are (the user's choice, 2026-11-03); others keep Java's name. Import takes the server's zone when Nuki's has the same offset now and at every change over ten years, as owners are most likely where the server is: a lock in Paris then comes in as `Europe/Madrid`, which its owner can change. Syncs never change the zone of a lock already imported, so an owner whose lock came in as `Europe/Berlin` changes it once. The settings list ids too, each with its name, as zones that share a name must be told apart there. |
| A time that is not a lock's (when a passkey was created and last used, when Nuki was last checked, when an invitation expires) is shown in the server's time zone (`TZ`, `Europe/Madrid` in the stack) with the zone's short name, CET or CEST (`format.datetime-zone`, review item ARC-07, 2026-11-20) | An owner has no time zone of their own, as their locks have. These were read without their zone (`::timestamp`, `LocalDateTime`), so what a page showed was the database session's or the JVM's zone, unsaid, and the night the clocks change one such time is two moments: with its name, 02:30 CEST and 02:30 CET are told apart. First shown in UTC; the server's zone is the user's choice the same day, as every lock is in it for now. The owner's activity and the admin panel's dates are in the same zone and do not say so yet |
| Configuration's pages under `/settings/...`, their former addresses redirecting (301) | Emails already sent link to `/nuki/connection`, `/notifications` and `/passkeys`: within a major version, every URL already sent keeps working. |
| The app's own error page; `/error` public; the session only in its cookie | Spring Boot's page broke the app's look, and a guest's error on a public route was redirected to /login, starting a session whose id Tomcat put in the URL (`;jsessionid=`). An unknown address still sends a visitor who is not signed in to /login, so no route shows it exists. |
| Tables too wide for a phone are cards below 1024 px (`table.cards`: attempts, activity, the admin's owners and unused links), as the links' already were; `td.main` and `td.aside` share the first line, `data-label` names a cell whose column heading is hidden | At 375 px the attempts' result, which is what the owner opens the page for, was a column off the screen (UX-01 of the 2026-11-19 review). One class for all of them rather than a layout per table. |
| An action that stops links or lets someone into an account asks first (`data-confirm`): disconnecting Nuki, a recovery link, making an admin, resuming a link | One tap did them (UX-08). Pausing does not ask: it opens nothing and is undone with one press. |
| What a button says after it is pressed goes back after 2 s (`copy.js`), a copy the browser refuses says so, and a button that starts a passkey ceremony is disabled and `aria-busy` until it ends (`WebAuthn.busy`) | "Copiado" stayed for ever, so a second copy looked like nothing; a refused copy looked like one that worked; a second press on "Entrar con passkey" started a second ceremony, which makes the first fail (UX-20). |
| A link's label inside a sentence is quoted, in each language's marks («Ana», "Ana", « Ana »), on the pages and in the emails | A label is free text, often with a comma: "Casa: Ana, fin de semana ha abierto la puerta" read as two things (TXT-02 of the 2026-11-19 review). The account emails already did. |
| Revoking is "Revoke", "Révoquer", "Revoca"; two days of a schedule are "Sábado y domingo", a run of three or more "Lunes a viernes" | "Disable" and its like sounded like something to undo, and pausing now is that; "Sábado a domingo" read as a range with something between (TXT-01, TXT-04). |
| The release shown beside the app's name in the menu, from Gradle's build info without its time; on owners' pages only | The user's choice (2026-11-21), to tell at a glance which release runs. The build's time is left out, as it would change the jar, and the image's application layer, at every build. Guests and visitors who are not signed in are not told, as it would tell anyone which release to look for flaws in; `edge` images show the version of the last release, as `build.gradle.kts` changes only when releasing. |
| The color theme in a cookie, not in the owner's row | The user's choice: it belongs to the browser, so a phone and a laptop may differ, and it also applies to the pages before signing in. The server writes `<html data-theme>`, so no script and no flash of the other theme; no cookie means the system's. |
| Pico CSS 2.1.1 kept, though Pico is unmaintained since 2.1.1 (repositories archived) | It is a static CSS file served from `static/css/` with no JavaScript, so there are no fixes to miss, and what it lacks goes in `app.css`. The templates lean on its classless styling of semantic HTML (`article`, `nav`, `fieldset role="group"`, `aria-busy`, `aria-current`, automatic dark mode): Bootstrap, Bulma or Pure would mean adding classes to every template for no visible gain, and Pure is barely maintained either. Revisit if a browser starts drawing something wrong that `app.css` cannot fix cheaply, or for a redesign; then prefer a fork of Pico, or own CSS keeping its variables. |

## Tests

- **Pages**: `HomePageTests` (locks, latest attempts, the same rows as the history, the menu with the version and `/settings`), `LockWarningsTests` (what is wrong with a lock on the home page and `/locks`, a lock that does not check where its guests are, a lock Nuki reports offline that has opened since, and a Nuki that fails or is slow), `ThemeTests` (the theme cookie and `data-theme` on every page), `TimeZoneNamesTests` (a lock's zone named alike on every page, ids only in its settings), `SignedInErrorPageTests` (the error page with the menu, through MockMvc and `/error`). What MockMvc does not show runs against a real server (`@IntegrationTest(webEnvironment = RANDOM_PORT)`): `ErrorPagesTests` (errors forwarded to `/error`, no session for guests, JSON for scripts) and `SessionCookieTests` (cookie flags, the session never in a URL).
- **On a phone**: `OwnerPagesTests` (an attempt's result is on the screen beside its date, on the home page and in the history; the copy button says what happened and then its name again; saving a lock stays on its page).
- **Accessibility**: `AccessibilityTests` runs axe-core (WCAG 2.2 AA and its best practices) on every page in the four languages, and in dark as well as light in the first of them, as dark changes only colours and contrast is the same in every language (a third of the tests' time, 2026-11-20); a violation fails the build. It cannot judge what a screen reader announces or the slider with VoiceOver or TalkBack, which only a person can try. A notice is an `<article aria-live="assertive">` (`role="alert"` is not allowed on `article`); text only for screen readers has the class `visually-hidden`. The menu starts with a skip link to `<main id="main">` (`OwnerPagesTests` tabs to it); every page's `<main>` keeps that id and `tabindex="-1"`. The keyboard's focus is a solid 3 px ring in `--pico-primary` (Pico's translucent halo is under WCAG 2.2's 3:1), tried in `OwnerPagesTests`. Reduced motion needs nothing of its own: Pico stops its transitions and animations under `prefers-reduced-motion: reduce` (the `aria-busy` spinner excepted, as it shows something is under way) and `open.js` reads the preference itself.
- **Languages**: `MessageBundlesTests` (bundles have the same keys and each message the same arguments, apostrophes are doubled, templates name only existing ones), `PagesInEveryLanguageTests` (every page in every language, no missing text), `TemplateTextTests` (no text in templates, escaped `th:utext`), `OwnerLanguageTests` (an owner's language, and that `app_user` may update no other column of `owner`).
